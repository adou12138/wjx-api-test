# 接口适用性判断与维度覆盖矩阵

> 用途：解决"不是每个接口都支持所有功能、不是每条规则都适用于每个接口"的问题。测试前必须先判断接口能力，再选择适用规则；不支持的功能标注 N/A，不强行套用。
> 来源：由 917 条真实接口缺陷复盘抽象，已去除业务耦合，适用于任意 HTTP/OpenAPI/REST/RPC 接口。
> 与 framework.md 的关系：framework.md 定义"测什么维度"，本文档定义"哪些维度适用于当前接口"。两者配合使用。

---

## 0. 四步判断法（测试前必做）

| 步骤 | 动作 | 产出 |
|------|------|------|
| 第 1 步 | 识别接口业务域 | 资源管理 / 数据查询 / 异步任务 / 鉴权 / 导出导入 / 通知推送 / 配置 / 文档 |
| 第 2 步 | 识别操作类型 | 查询（列表/详情）/ 创建 / 修改 / 删除 / 导出 / 导入 / 订阅 / 配置 |
| 第 3 步 | **判断是否国际版场景** | 见下方"国际版判定"；国内版 → 国际版维度全部 N/A |
| 第 4 步 | 筛选适用规则 | 从 framework.md 取通用维度 + AA–AE 补充维度 + 从本文档 §3 取对应业务域专项 |
| 第 5 步 | 标注不适用项 | 接口不支持的功能标注 **N/A**，不强行测试、不计入通过率，但必须列出证明已判断 |

### 国际版判定（第 3 步）

> **默认按国内版处理**：国际版维度（framework §1.3）一律标 N/A，不加载、不计入覆盖率分母。

满足**任一**条件才加载国际版维度：
1. 用户明确说明测的是国际版 / 海外版 / 多语言站点；
2. 接口文档或响应中出现 `language` / `locale` / `currency` / `timezone` / `tz` / `i18n` 字段；
3. 被测环境域名为海外站点，或账号归属海外区域；
4. 接口涉及金额、跨时区时间、多语言文案中的任一项。

未启用时在覆盖率矩阵中统一标注 `N/A（非国际版）`。

## 1. 操作类型与测试重点对应表

| 操作类型 | 必测维度 | 重点场景 | 典型不适用项 |
|---------|---------|---------|-------------|
| **查询（列表/详情）** | 参数校验、鉴权、数据一致性、分页/筛选/排序、错误处理、字段完整 | 字段是否齐全、分页边界、筛选生效、排序方向、时区正确、跨账号越权 | 状态机、导出下载、导入、Webhook 推送 |
| **创建** | 参数校验、鉴权、权限、业务类型边界、幂等、数据一致性（创建后回查） | 必填/枚举/长度/格式、越权创建、重复创建、创建后字段与请求一致 | 答卷下载、发送、评价关系（除非接口本身支持） |
| **修改** | 参数校验、状态机、权限、资源归属、幂等、部分更新语义、数据一致性（修改后回查） | 非法状态修改、越权修改、不传字段=不修改还是清空、修改后回查 | 导出下载、导入 |
| **删除** | 状态机、权限、资源归属、幂等、级联影响、错误提示 | 已删除再删、越权删除、删除后关联资源行为、提示明确 | 分页筛选、导出 |
| **导出/下载** | 参数校验、空数据、数据完整性、格式、链接有效期、权限 | 无数据提示、导出选项生效、数据口径正确、范围校验、下载链接可访问 | 状态机（除非导出触发状态变更）、Webhook 推送 |
| **导入** | 参数校验、数据合法性、部分成功、错误定位、幂等、权限 | 非法数据处理、部分成功返回、重复导入、越权导入 | 分页筛选、导出下载 |
| **订阅/Webhook** | 参数校验、权限、订阅对象校验、事件触发、重试、补推 | 订阅已删除对象、事件不触发、失败重试、暂停恢复补推 | 分页筛选、导出 |
| **配置类（QPS/限流/IP）** | 参数校验、权限、生效验证、边界 | 配置值范围、配置后是否生效、主/子账号隔离 | 答卷下载、评价关系 |

> 维度编号对照：上表中的"分页/筛选/排序"→ **AA**，写在"幂等"位置的能力 → **AC**，"Webhook 推送" → **AD**。
> 另外 **AB（前端-接口口径一致性）适用于所有有对应页面的接口**，与上表操作类型无关，只要被测接口在前端有对应操作就必须测。

## 2. 关键反例（必须避免的错误套用）

- ❌ 创建资源接口 → 检查资源下载（创建后无下游数据，下载功能不适用）
- ❌ 获取列表接口 → 检查状态机（查询接口不改变状态）
- ❌ 通讯录接口 → 检查多角色评价关系（业务域不相关）
- ❌ 鉴权 token 接口 → 检查分页筛选（无列表数据）
- ❌ Webhook 创建接口 → 检查导出下载（业务域不相关）
- ❌ 普通资源接口 → 检查专项业务规则（如非 360 接口不检查评价级别）
- ❌ 单条操作接口 → 检查批量部分成功语义（操作类型不匹配）

## 3. N/A 标注规范

测试用例中对不适用的规则统一标注：

| 标注 | 含义 | 示例 |
|------|------|------|
| `N/A - 接口不支持该功能` | 接口本身无此能力 | 创建问卷不支持答卷下载 |
| `N/A - 该操作类型不涉及` | 操作类型不触发此维度 | 查询接口不涉及状态机 |
| `N/A - 业务类型不匹配` | 业务域/类型不支持 | 普通问卷不涉及 360 评价 |
| `N/A（非国际版）` | 国内版测试不加载国际版维度 | 多语言 / 时区 / 多币种 / 错误信息国际化 |

> 不适用项**不计入通过率**，但必须在测试报告中列出，证明已判断而非遗漏。

## 5. 业务域专项速查（17 簇，详见 framework.md §2 M–Z）

| 业务域 | 专项编号 | 核心测试点 | 适用接口 |
|--------|---------|-----------|---------|
| 资源导出/下载 | M | download_url、导出选项、数据口径、链接有效期、空数据 | 导出/下载接口 |
| 层级资源管理 | N | 层级上限、父级只读、树形返回、管理员三态、自定义字段 | 通讯录/标签/部门/文件夹 |
| 异步通知/发送 | O | 定时时区、列表字段、重发枚举、提醒参数、渠道枚举 | 发送/通知接口 |
| 分享/链接参数 | P | 渠道状态枚举、状态联动、参数去重、分享方式 | 分享/链接接口 |
| 多角色关系 | Q | 自评一致性、级别数量、覆盖语义、已有数据限制 | 评价/关系接口 |
| 报告/结果分享 | R | 报告类型、分享条件、互斥、密码 | 报告分享接口 |

## 6. 通用补充维度速查（AA–AE，详见 framework.md §2）

与业务域无关、按**接口形态**判定的补充维度：

| 维度 | 编号 | 适用条件 | 核心测试点 |
|------|------|---------|-----------|
| 分页与列表查询 | **AA** | 所有列表 / 分页查询接口 | 页码与条数边界、total 一致、排序稳定、筛选真生效、空结果、字段不冗余 |
| 前端-接口口径一致 | **AB** | **所有有对应页面的接口** | 权限 / 校验 / 展示 / 枚举 / 默认值 / 边界 六类口径与页面一致 |
| 幂等与业务唯一性 | **AC** | 所有写接口 | 重复提交幂等、业务唯一性、列表去重、冲突值回显、并发幂等 |
| 事件与回调 | **AD** | 会触发事件 / 回调的接口，及 Webhook 管理接口 | 事件完备、不重不漏、载荷准确、订阅范围、重试补推、顺序、并发一致 |
| 认证/传输补充 | **AE** | **所有接口**（六种操作类型的必测元组均含 AE） | 认证生命周期与失效返回码、凭证缺失与错形、请求头与传输契约、重放时间窗、401/403 不得混用 |

> **AB 是最容易被整体跳过的一个维度**：它不体现在操作类型里，纯接口视角 100% 测不出来，但历史缺陷中占比约 8.4%。只要接口在前端有对应操作，就必须测。
>
> **AE 是文档最容易整类漏掉的一个维度**：认证与传输语义由公共层承载，单接口契约几乎不写，因此文档里常常没有它的落点——但代码侧它恒为必测。**不应因为契约没写就跳过 AE**。

## 7. 高频缺陷启发式检查表

设计用例前先过一遍 `references/defect_patterns.md`（12 条 Top 高频缺陷模式 + 7 条补充模式），逐条确认本接口是否可能命中，把命中的模式转成用例挂到对应维度下。
