# 问题记录规范（CSV）

每条问题统一字段，便于结构化追踪与复盘、并可直接导入 Excel/WPS。

## 列结构（逗号分隔，首行表头；字段含逗号/引号/换行时用双引号包裹）

**统一 16 列 = 基础 9 列 + 证据链 7 列**，两种导出路径（深度流程 `api_test_runner`、
声明式执行器 `case_runner`）**共用同一份列定义**
（唯一来源 `api_test_runner.FINDING_CSV_COLS`，渲染函数 `finding_row()`）——
不得各写一份表头，否则会出现"同一份台账两套口径"。

```
编号 | 类型 | 严重程度 | 状态 | 维度 | 问题描述(现象化) | 请求Body | 预期结果 | 实际结果
| 置信度 | HTTP状态码 | 请求ID | TraceID | 证据路径 | 归因 | 复测状态
```

### 基础 9 列

| 列 | 说明 |
|---|---|
| 编号 | 用例/登记表编号（如 `B8-2`、`AB3-01`）；覆盖率缺口用 `COV-<用例id>` |
| 类型 | 见下方枚举取值 |
| 严重程度 | 高 / 中 / 低 / 信息 / 无 |
| 状态 | 待修复 / 符合预期 / 待确认 / 已确认非问题 |
| 维度 | 触发该问题的维度编号（如 `B3`/`AA3`/`H9`），用于按维度统计缺陷产出、反哺 `defect_patterns.md`；不明确可留空 |
| 问题描述 | **现象口吻**，见填写要点 |
| 请求Body | 真实完整报文（含公共参数），见下方铁律 |
| 预期结果 | 应表现出的行为；异常用例写明期望命中的错误关键词 |
| 实际结果 | 实际观测；FAIL 且触发最小化时，末尾自动附「最小复现请求：…」 |

### 证据链 7 列（此前只有列头、值恒空）

| 列 | 写入者 | 说明 |
|---|---|---|
| 置信度 | `add_finding(confidence=)` | 默认 `0.8`；<0.8 表示推断项，只进探索性测试/待确认清单 |
| HTTP状态码 | `add_finding(http_code=)` | 响应状态码；无请求（如覆盖率缺口）留空。5xx 一律记问题 |
| 请求ID | `add_finding(request_id=)` | 服务端返回的 request id，用于向开发取证 |
| TraceID | `add_finding(trace_id=)` | 链路追踪 id（有则记，便于跨服务定界） |
| 证据路径 | `add_finding(evidence_path=)` | 脱敏证据包/原始响应的落盘路径 |
| 归因 | `attribution_engine` | `ENV` / `RATE_LIMIT` / `CONSISTENCY_PENDING` / `NEEDS_CONFIRMATION` / `DEFECT` / `PRECONDITION_UNMET`；**类别清单以 `references/attribution_rules.md` 为准**。ENV 与 RATE_LIMIT 不计入缺陷；`PRECONDITION_UNMET`（前置条件未满足，需已确认依赖才生效）既不算失败也不算通过，但同样**不进缺陷台账** |
| 复测状态 | `add_finding(retest_status=)` | 默认「待复测」；复测后回写「已修复(附证据)/仍存在/新发生」 |

## 枚举取值
- **类型**：缺陷 / 待确认 / 已确认非问题 / 符合预期(安全拦截) / 环境风险(ENV) / 需求确认 / 文案优化 / 建议项 / 样式问题
  - 缺陷子类（来自 917 条真实缺陷复盘，建议在描述中标注）：功能问题 / 参数校验缺失 / 过度校验(误拒合法输入) / 状态机错误 / 权限越权 / 数据不一致 / 分页筛选错误 / 并发问题 / 错误语义不准 / 错误码映射错误 / 文档与实现不一致 / 时区问题 / 字段命名错误 / 枚举不完整 / 部分成功语义缺失 / 幂等与业务唯一性 / 事件推送异常(漏推/重推/载荷不准)
- **严重程度**：高 / 中 / 低 / 信息 / 无
- **状态**：待修复 / 符合预期 / 待确认 / 已确认非问题
- **维度**：触发该问题的维度编号（如 `B3` / `B8` / `AA3` / `H9`，见 framework.md §2），用于按维度统计缺陷产出、量化反哺 `defect_patterns.md`；不明确时可留空。

## 填写要点
- **问题描述用"现象"口吻**，避免纯技术术语。例：「在内容里写入网页脚本也能保存，需确认别人打开时脚本会不会真的被执行」。
- **请求 Body 须记录【真实完整报文】**（含公共固定参数 `encode`/`appid`/`action`/`sign`/`ts`），便于开发直接复现。**这是硬规则，不是可选项**——问题单里看到的请求参数必须和接口实际收到的请求一致，少一个公共参数开发都无法原样复现。
  - **公共参数清单**（每个请求都带，值固定，参见 `env_config.md` 登记）：`encode`（编码/签名算法，如 `sha1`）、`appid`（当前环境统一 appid，如 `<APPID>`）、`action`（业务动作码，随接口变）、`sign`（签名值，约定不校验时仍要记录）、`ts`（Unix 时间戳，每次请求变化）。
  - **仅当缺陷本身涉及「缺某公共参数」时才省略该字段**（如"缺 action 仍成功"的用例，body 故意不含 action）。其它情况下，公共参数与业务参数**一并记录**。
  - `ts` 用占位符（如 `<请求时unix时间戳>`）标明即可，不写死具体值（每次请求都变，写死反而误导）。
  - **运行器已自动补齐**：`scripts/api_test_runner.py` 的 `add_finding()` 会对含 `action` 字段的原始请求报文自动补齐全公共参数（缺失才补、不覆盖已显式传的值），所以**用运行器模板写用例时无需手工拼公共参数**；独立脚本（不调用运行器 helper）必须在记录请求体时自行补齐公共参数，否则就是不完整台账。
  - **正例**（完整，开发可原样复现）：
    `{"encode":"sha1","appid":"<APPID>","action":"1006001","ts":"<请求时unix时间戳>","sign":"1234","include_sub_account":1}`
  - **反例**（不完整，缺公共参数，禁止）：
    `{"action":"1006001","include_sub_account":1}` ← 缺 `encode`/`appid`/`sign`/`ts`，开发无法复现，必须改正。
- **预期 / 实际**要可对照，异常用例写明期望命中的错误关键词。
- 安全拦截类（如注入被正确拦截）记「符合预期」，不要误记为缺陷。
- （仅当确实做了多环境对比、且观察到环境差异时）多环境行为不一致记「环境风险(ENV)」，不要擅判缺陷或漏报。默认单环境测试不需要此项。
- **不适用项（N/A）不记入问题台账**：接口不支持的功能（如创建接口不查导出下载）在测试用例中标注 N/A 即可，不产生问题记录。详见 `applicability_matrix.md`。
- **覆盖率缺口要记，逐条与维度两级都记**：它与"接口有缺陷"不同——描述的是**测试没做到**，不允许静默略过。生成 `COV-*` 编号的【缺陷(覆盖率缺口)】入台账，维度填该用例所属维度。
  - **逐条级**：任何**已生成却未执行**的用例（`needs=manual`、命中需外部能力的检查、无基线可比的 AB 项）在跳过前先记一条 `COV-<用例id>`——结果行上的 `SKIPPED` 不是台账，只有台账才会被交付与复盘看到。
  - **维度级**：收尾门禁再判一次"某必测维度无任何 PASS/FAIL 用例"，兜底捕捉"整个维度没生成用例或整批未跑"。
  - 两级缺一不可：维度级只在**整维度颗粒无收**时报警；若同维度另有用例跑过，逐条级是唯一留痕处。
- **需求确认类**：接口行为与文档不一致但不确定哪边对时，先记「需求确认」而非直接判缺陷，待产品/开发确认后再转缺陷或符合预期。
- **文案优化类**：错误提示文案不准确/不友好（如写"每年"实为"每周"），记「文案优化」，严重程度通常为低。

## 导出格式
- 用 `UTF-8 with BOM`（`utf-8-sig`），逗号分隔；字段内含逗号、双引号或换行时，用双引号包裹该字段，且字段内双引号写成两个双引号（`""`），避免 Excel/WPS 打开错位。
- runner 脚本已按此导出 `api_test_issues.csv`（全量 16 列）与 `api_test_observations.csv`（待确认子集）。
