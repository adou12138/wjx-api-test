# 测试环境登记（只登记当前要测的那一个）

把"固定参数（编码 / 签名 / AppID / 账号）"集中登记，避免散落在各份用例里、便于核对不错配。**默认只在用户当前指定的那一个环境测试，不需要列举本地/预发布/生产等所有类别**——本文件填一个环境就够了。本文件供 `scripts/api_test_runner.py` 的【基础配置】块配套使用。

> **本文件是模板**：登记模板是通用的，适用于任意接口。下方"参考实例"仅作格式示范，**接入新接口时可直接删除实例部分**，只填你当前要测的那一个环境即可。

## 分类原则

- 可按"环境性质"给当前环境贴个标签（本地 / 测试环境、预发布环境、生产环境），但**只填当前要测的那一个**即可，不需要把各类都列全。
- 同性质多实例归一类，差异在备注列明（例如同一台服务器的不同域名指向同一后端）。
- 账号随"环境类别 + appid"成对记录，主 / 子账号一并写，避免混用导致越权类用例判错。
- 签名若约定"不校验"，显式标注，并在对应鉴权维度（框架 §2 A 系列）用例里反向验证（错误 sign 是否仍成功）。
- **仅测国际版时**：在登记模板备注中额外登记默认语言（language/locale）、默认币种（currency）、默认时区（timezone）及其参数字段名——国际版维度（框架 §1.3）的 `check_currency()` / `check_datetime_tz()` / `check_error_i18n()` 依赖这些信息构造用例。国内版测试不需要。
- 本地 / 测试环境常有未文档化强校验、规则漂移；**仅当确实做了多环境对比**且观察到差异时，才记入 ENV 台账，不擅判缺陷。单环境测试可跳过。

## 登记模板

```
【<环境类别> · <appid>】<环境标识列表>
  BaseURL : <默认域名>   （若有多域名/内网穿透，注明优先项）
  路径    : <path>       方法: POST   encode: <sha1/...>
  appid   : <appid>
  sign    : <sign>        （约定：不校验 / 需校验）
  主账号  : <main>        子账号: <sub>
  备注    : <规则漂移/可达性差异/域名关系>
```

## 在 runner 中切换环境

- 测试地址通过环境变量传入，不写死进脚本：
  ```bash
  WJX_BASE_URL=https://你的实际地址/实际路径 python api_test_runner.py
  ```
- 改 appid / 账号 / 签名：编辑脚本顶部【基础配置】块。
- 多环境对比（**非必需，默认不要求**）：仅当用户明确要求、或确实要核对跨环境一致性时，分别用不同 `WJX_BASE_URL` 跑两遍，把同一用例在两类环境的"通过 / 拒绝 / 错误文案"差异记入 ENV 台账。
