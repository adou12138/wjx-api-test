# UI 页面基线登记表（AB 维度配套资产）

> **为什么需要**：AB（前端-接口口径一致性）是纯接口视角 100% 测不出的缺陷模式（历史缺陷占比约 8.4%，第二高发）。
> 测 AB 的前提是拿到**页面基线**——`check_ui_parity(api_value, page_value)` 里的 `page_value` 不能凭想象填，
> 必须来自本表登记的真实页面观测值。没有基线，AB 维度只能记「缺口」，不得声称已覆盖。

## 1. 基线的三种来源（按可信度与成本选择）

| 来源 | 方式 | 适用场景 | 注意事项 |
|---|---|---|---|
| **人工页面操作**（默认） | 测试人员在页面上实际操作/查看，把显示值记录到下表 | 抽查式 AB 测试、页面数量少 | 必须**实际操作后记录**，禁止凭需求文档/记忆填；同一字段在不同状态下可能显示不同（如编辑页 vs 详情页），按状态分行登记 |
| **浏览器自动化抓取** | 用 Playwright / agent-browser 等工具打开页面读取 DOM 值 | 页面多、需回归时批量取基线 | 抓取值是"当前实现"，若当前实现本身有缺陷会被固化成基线——首次建基线仍需人工复核一遍 |
| **设计稿 / 原型** | 从 figma-ui-parity 等设计稿比对 skill 读取预期展示 | 有设计稿的新功能、走查场景 | 设计稿≠实现，仅作预期值；实测偏差走 AB 缺陷流程 |

> **纪律**：基线值记录到本表后**注明来源与日期**。页面改版后基线须同步更新，过期基线会把正确实现误判成缺陷（同类陷阱见"回归复测专项"的过期期望误报）。

## 2. 登记表模板（复制使用）

```markdown
## UI 页面基线登记（<接口 action> <接口名>）

| 编号 | 页面/入口 | 页面操作/位置 | 口径类型 | 接口字段 | 页面基线值（实际观测） | 来源 | 记录日期 | 记录人 |
|---|---|---|---|---|---|---|---|---|
| AB1-01 | 共享文件夹详情页 | 问卷管理员右键菜单 | 权限口径 | （行为类）删除/编辑是否可用 | 页面【可编辑】 | 人工 | 2026-09-08 | 张三 |
| AB3-01 | 问卷列表页 | 创建时间列 | 展示口径 | data.list[].created_at | 页面显示 2026-09-08 14:30（本地时区） | 人工 | 2026-09-08 | 张三 |
| AB4-01 | 新建问卷页 | 类型下拉框 | 枚举口径 | q_type 允许值集合 | 页面下拉共 5 项：1/2/3/4/5 | 抓取 | 2026-09-08 | 张三 |
| AB5-01 | 新建问卷页 | 未填写的说明字段 | 默认值口径 | description 缺省值 | 页面新建后默认为空串 | 人工 | 2026-09-08 | 张三 |
| AB6-01 | 标签管理页 | 新增标签输入框 | 边界口径 | name 长度上限 | 页面输入 21 字被截断/提示，实际上限 20 | 人工 | 2026-09-08 | 张三 |
| AB2-01 | 设置页 | 说明字段留空保存 | 校验口径 | description 可空性 | 页面【允许保存】 | 人工 | 2026-09-08 | 张三 |
```

口径类型与 AB 子维对应：AB1 权限 / AB2 校验 / AB3 展示 / AB4 枚举 / AB5 默认值 / AB6 边界。
**行为类口径**（AB1/AB2）记录"页面允许/不允许"；**值类口径**（AB3–AB6）记录具体显示值或集合。

## 3. 使用方式（与运行器衔接）

**两条路径**：手工路（第 2 节登记表 → 手写 `check_ui_parity()`）与自动路（第 6 节 JSON 基线
→ `ui_baseline.py` 加载 → 用例 `check="ui_parity"` 自动比对）。自动路是让 AB 从"永远跳过"
变成"真跑得起来"的关键，推荐先用自动路。

```python
# 页面基线登记表填好后，逐条转成 check_ui_parity 断言：
ok, msg = check_ui_parity(api_created_at, "2026-09-08 14:30", aspect="展示口径", field_name="created_at")
# ok=False 即 AB 缺陷：接口返回值与页面基线不一致，记入台账（维度填 AB3-01 等登记表编号）
```

- 比对**不一致** → 缺陷，问题描述用现象口吻（"页面显示 14:30，接口返回 06:30，前后端口径不一致"）；
- 比对**一致** → 该 AB 项记「强覆盖」，登记表编号写入覆盖率矩阵 §4 的证据列；
- **拿不到基线**（无页面/无法登录页面）→ 该 AB 项标 **N/A 或缺口**，不得凭空填 page_value。

## 4. 最小基线集（快速版）

时间紧张时，至少登记这 4 条高发基线（历史缺陷重灾区）：
1. **共享/协作/子账号场景的权限口径**（AB1）——"页面可操作 ⟺ 接口可操作"；
2. **时间的页面显示**（AB3）——时区/格式（历史缺陷：差 8 小时）；
3. **枚举下拉项集合**（AB4）——不多不少；
4. **必填标识与默认值**（AB2/AB5）——页面标必填的接口是否真校验、页面默认值接口是否一致。

## 5. JSON 基线格式（机器可读，自动路专用）

登记表是给人看的；执行器读的是 JSON。两者字段一一对应，登记完转写即可。

**存放位置**（按优先级，`scripts/ui_baseline.py` 的 `_paths()`）：

1. 命令行 `--ui-baseline <path>`（用例 `check_args.baseline_path` 亦可）；
2. 环境变量 `WJX_UI_BASELINE`；
3. `~/.workbuddy/wjx-api-test/ui_baseline.json`（**真实基线放包外**）；
4. skill 内 `assets/ui_baseline.json`（默认不存在，包内只放 example 模板）。

**结构**：

```json
{
  "template": false,
  "baselines": [
    {
      "field": "created_at",
      "action": "1000107",
      "dimension": "AB3",
      "aspect": "展示口径",
      "page_value": "2026-09-22 16:30",
      "source": "人工",
      "captured_at": "2026-09-22",
      "note": "AI主页列表页创建时间列"
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `field` | 是 | 接口响应 `data` 里的字段名；缺 `field` 的行会被整行跳过 |
| `page_value` | 是 | **页面上实际观测到的值**。类型要与接口返回值可比较（字符串就都写字符串，避免 `"1"` vs `1` 假不一致） |
| `action` | 建议 | 限定所属接口；留空则该字段对任意 action 生效 |
| `dimension` | 否 | 默认 `AB`；填 `AB1`–`AB6` 便于按子维度统计 |
| `aspect` | 否 | 口径类型（权限/校验/展示/枚举/默认值/边界），默认「口径」 |
| `source` | 建议 | 人工 / 抓取 / 设计稿——过期基线会把正确实现误判成缺陷，来源与日期是复核依据 |
| `captured_at` | 建议 | 记录日期；页面改版后须同步更新 |
| `note` | 否 | 页面位置、状态（编辑页 vs 详情页）等语境 |

**执行语义（二分，见 `case_runner._check_ui_parity`）**：

- 字段**有**基线 → 逐字段比对，不一致记缺陷（AB 真正被执行，计入"已覆盖"）；
- 字段**无**基线 → 记 `COV-*`【覆盖率缺口】，**不算已覆盖、不编预期值**；
- 基线文件整个找不到 → 同样记缺口，不静默跳过。

**占位模板保护**：`assets/ui_baseline.example.json` 带 `"template": true`，
加载器会**主动跳过并打印说明**——模板里的"示范页面值"是格式样例而非实测值，
若当成真实基线比对，会把正确实现误判成 AB 缺陷（"假预期造出假缺陷"）。
复制自用时**请删除 `template` 字段**并把每行 `page_value` 换成实测值。

- 本实例同时示范了与 **1000107 真实冒烟**（`references/real_smoke_delivery.md`）的衔接：冒烟 PASS 后，用本表逐条核对回读值与页面口径。
