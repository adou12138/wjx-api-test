# 缺陷模式候选池

> 候选只作为待评审素材，不自动并入正式缺陷模式清单。
> **纪律**：候选先进本池，评审通过后才并入 `defect_patterns.md`（正式清单）并同步到 `pattern_engine.py` 规则。每条候选必须带证据（缺陷现象 + 触发用例来源），无证据的候选不得并入。

## 登记方式（`scripts/pattern_feedback.py`）

闭环的最后一环：把本轮新发现、"现有 19 条模式没覆盖"的缺陷抽象成候选，回流待评审。同一维度下现象高度相似的候选会合并计数，避免刷屏；已被正式清单覆盖的现象不再登记。

```bash
# 从问题台账自动提炼候选（按行提炼「缺陷」类条目，聚合去重后登记）
python scripts/pattern_feedback.py --from-csv api_test_issues.csv

# 手工登记一条（--add 必须同时给出 --dim 与 --symptom）
python scripts/pattern_feedback.py --add --dim B8 --symptom "可选字段传空被拒" --evidence "用例 B-NULL-xx"
```

| 参数 | 说明 |
|---|---|
| `--from-csv` | 从问题台账 CSV 自动提炼候选（读 16 列台账的「类型/维度/问题描述/编号」列，只取「缺陷」类，按维度+归一化现象聚合） |
| `--add` | 手工登记一条候选；未同时提供 `--dim` 与 `--symptom` 时报错退出 |
| `--dim` | 候选所属维度编号（如 `B8` / `H6`） |
| `--symptom` | 缺陷现象，用现象口吻描述（如"可选字段传空被拒"） |
| `--evidence` | 证据 / 触发用例来源；`--add` 时省略则记「人工登记」 |

`--from-csv` 与 `--add` 必须给其一，都不传时直接报错退出（`需指定 --from-csv 或 --add`）。本脚本**只写候选池**，不改 `defect_patterns.md`、不改 `pattern_engine.py` 规则；已被正式清单覆盖的现象（现象前 8 字命中清单标题）会自动跳过，不重复登记。
