# wjx-api-test 配置参数说明（配置项 ↔ Sojump 接口参数 ↔ 中文含义）

> 本文件把 skill 里所有**配置项**一一对应到 Sojump OpenAPI 的**接口参数字段**，写清每个参数"是什么、从哪来、怎么填"。
> 配置分两类：
> 1. **个人参数**（深度测试 + 冒烟共用，单一来源）→ `personal_config.json`（模板见 `personal_config.example.json`）
> 2. **冒烟环境配置**（仅冒烟模块，广度探活用）→ `smoke_config_*.json`
>    - `smoke_config.example.json` = **通用模板（分享用，占位符、零个人数据）**，团队外部用这一份；
>    - 含真实值的实例配置（如 `smoke_config_cw.json`、`personal_config.json`）一律放**包外** `~/.workbuddy/wjx-api-test/`，不要放入 skill 包内，运行时用 `--config` / `--personal` / `WJX_CONFIG` 显式指定。两者结构完全一致，仅是否填真实值不同。
>
> 所有"个人值"（appid / 账号 / 域名 / corpid）一律外置，**模板里只留占位符**，运行时由 `personal_config.json` 或 `WJX_*` 环境变量解析。详见 `SKILL.md` 的"个人参数配置"章节。
> 下文示例值（如 `1000000` / `your_main_account`）均为**中性演示占位**，请替换为你自己的真实环境值。

## 一、个人参数 `personal_config.json`（核心，深度测试 + 冒烟共用）

| 配置键 | 对应接口参数字段 | 中文名 | 含义 | 取值示例 | 必填 | 备注 |
|---|---|---|---|---|---|---|
| `base_url` | 接口地址（契约文档『接口地址』字段） | 接口基础地址 | HTTP 请求的根 URL + 路径，脚本所有请求的发送目标 | `https://your-env.sojump.cn/openapi/folder.aspx` | **必填** | 必须取自契约文档实际地址，禁止写死示例域名；冒烟模块会从中解析出 `<域名>` 占位符 |
| `appid` | `appid` | 应用ID | 所有请求都带的**公共参数**，唯一标识你的企业 / 应用 | `1000000` | **必填** | 切环境即换 appid |
| `sign` | `sign` | 签名值 | 所有请求都带的**公共参数**；当前约定"不校验"，填任意固定值即可 | `1234` | **必填** | 约定不校验时填 `1234` 这类占位值即可；若将来启用签名校验需按规则生成 |
| `main_account` | `creater` / `creater_main` | 主账号 | 作为请求参数下发的**创建者主账号登录名** | `your_main_account` | **必填** | 用于按创建者维度验证（如"我创建的文件夹"）；具体字段名以契约文档为准 |
| `sub_account` | `creater_sub` | 子账号 | 作为请求参数下发的**创建者子账号登录名** | `your_sub_account` | 可选 | 子账号维度用例、横向越权用例使用 |
| `corpid` | `corpid` | 企业ID | 标识企业主体，部分接口（企业微信 / 企业相关）需要 | `org0000000000` | 可选 | 视接口是否需要企业维度 |
| `sysid` | `sysid` | 系统ID | 业务系统标识，仅部分接口需要 | `100001` | 可选 | 仅特定接口 / 冒烟 `overrides.sysid` 使用 |
| `cross_appid` | `appid`（另一企业） | 跨企业 appid | A 系列**跨企业隔离**用例用的"另一家企业"的 appid | `2000000` | 可选 | 仅跨企业租户隔离测试需要；未配置时该用例自动跳过 |

> **说明**：`encode`（编码/签名算法，固定 `sha1`）、`ts`（Unix 时间戳，每次请求自动生成）、`action`（业务动作码，如 `1006001`，随用例/案例变化）这三个公共参数**不进配置文件**——`encode`/`ts` 由脚本自动补齐，`action` 写在用例里。详见第三节。

## 二、冒烟环境配置 `smoke_config_*.json`（仅冒烟模块，广度探活）

该文件描述"怎么批量探活一群接口"，个人值用占位符，运行时由 `personal_config.json` 解析。

| 配置键 | 含义 | 与接口参数的关系 / 取值 |
|---|---|---|
| `name` | 环境展示名 | 由 `<域名>` 占位符解析（来自 `personal_config.base_url` 的域名部分） |
| `base_url` | 接口地址模板 | `https://<域名>/openapi/{endpoint}`，`<域名>` 由 personal 解析；`{endpoint}` 在案例里按接口替换 |
| `default_endpoint` | 默认接口路径 | 如 `default.aspx` / `folder.aspx`，案例未指定 endpoint 时使用 |
| `method` | HTTP 方法 | 固定 `POST` |
| `timeout` | 请求超时 | 秒，默认 `60` |
| `tls_verify` | 是否校验 TLS 证书 | 测试环境证书多为自签，默认 `false`（不校验） |
| `action_param` | 动作码参数名 | 一般是 `action`，案例通过它传 `1006001` 这样的业务码 |
| `common_params.encode` | 公共参数 `encode` | 固定 `sha1` |
| `common_params.appid` | 公共参数 `appid` | 占位符 `<APPID>`，由 personal 解析 |
| `common_params.sign` | 公共参数 `sign` | 占位值 `1234`（约定不校验） |
| `common_param_generators.ts` | 公共参数 `ts` 生成方式 | `unix_ts`：每次请求自动生成 Unix 秒级时间戳 |
| `account.main` / `account.sub` | 主 / 子账号 | 占位符 `<主账号>` / `<子账号>`，由 personal 解析，用于需要创建者维度的案例 |
| `qps_tiers` | 限流档位 | 并发数 → 请求间隔秒（如 `"10": 0.12` 表示并发 10 时每条间隔 0.12s），用于节流防 429 |
| `error_retry` / `error_retry_sleep` | 错误重试 | 网络/5xx 错误重试次数与间隔（秒） |
| `teardown_enabled` | 收尾清理开关 | `false` 默认不清理；需删除测试数据时显式 `--allow-cleanup` 开启 |
| `env_keywords` | 环境干扰关键词 | 响应含这些词（如"频率过快""网络"）判为环境限制（ENV），不计缺陷 |
| `na_keywords` | 不适用关键词 | 响应含这些词（如"未开通""已废弃"）判为 N/A（该接口在本环境不适用） |
| `overrides` | 业务专属数据 | **必须按你的真实接口重新生成**：各字段已在模板内用尖括号写明自身含义，请勿原样使用演示值。关键字段对照如下 |

> **占位符清单**（冒烟配置里只写这些，不要写死真实值）：
> 简短形式：`<APPID>` `<主账号>` `<子账号>` `<CORPID>` `<SYSID>` `<域名>`；
> 或**自带中文接口参数含义的长串形式**（推荐，见 `smoke_config.example.json`）：`<appid 应用ID：...>` `<creater_main 主账号：...>` `<creater_sub 子账号：...>` `<corpid 企业ID：...>` `<sysid 系统ID：...>` `<域名：接口根域名，由 personal_config.base_url 解析，如 your-env.sojump.cn>`。
> 两种写法都解析为同一字段，全部由 `personal_config.json` / `WJX_*` 解析，旧配置（简短形式）不失效。

**`overrides` 各字段含义对照**（均在 `smoke_config.example.json` 内以尖括号自解释）：

| overrides 字段 | 对应业务 / 接口参数 | 中文含义 | 是否自动解析 |
| --- | --- | --- | --- |
| `minimal_questions` | 题目 JSON 数组 | 冒烟用的极简题目（q_index/q_type/q_title/is_requir/items），须按真实接口重新生成 | 否（按接口填） |
| `tiny_png` | 图片/附件样本 | 1x1 透明 PNG 的 base64，作为最小化样本，须按真实接口替换 | 否 |
| `settings_vid` | 设置接口 vid | 问卷/设置接口的 vid，标识某项设置 | 否 |
| `usersystem_vid` | 用户体系 vid | 用户体系接口的 vid，标识用户体系配置 | 否 |
| `usersystem_uid` | 用户体系 uid | 用户体系接口的 uid，标识具体用户 | 否 |
| `response_vid` | 作答接口 vid | 作答/回收接口的 vid，标识一份作答记录 | 否 |
| `survey_360_vid` | 360 接口 vid | 360 评估接口的 vid，标识一份 360 评估 | 否 |
| `modify_vid` | 修改接口 vid | 修改接口的 vid，标识被修改的对象 | 否 |
| `modify_score_key` | 修改评分 key | 修改评分项的 key，标识具体评分维度 | 否 |
| `submitdata` | 提交数据体 | 提交作答的数据体（与题目结构对应） | 否 |
| `modify_submitdata` | 修改数据体 | 修改作答的数据体 | 否 |
| `sysid` | `sysid` | 系统ID，仅部分接口需要 | **是**（← personal `sysid`） |
| `corpid` | `corpid` | 企业ID，标识企业主体 | **是**（← personal `corpid`） |

> 说明：`sysid`/`corpid` 两个字段在模板中写的是「`<sysid 系统ID：...>`」「`<corpid 企业ID：...>`」长串占位符，运行时由 `personal_config.json` / `WJX_*` 自动替换；其余 `vid`/`uid`/`submitdata` 等是接口专属业务数据，解析器不处理，须按你的真实接口生成后填入。

## 四、占位符解析机制（一句话）

`scripts/personal_config.py` 的 `load_personal_config()` 按 **环境变量 > personal_config.json > 报错** 加载个人值；
`resolve_placeholders()` 把冒烟配置与生成用例（越权矩阵的身份参数）中的 `<APPID>` `<主账号>` `<子账号>` `<跨企业appid>` `<CORPID>` `<SYSID>` `<域名>` 统一替换为上述真实值（`<域名>` 由 `base_url` 解析出域名部分）；解析不到的占位符**原样保留**，由调用方报错跳过并点名，不静默替换成空串。
任何必需参数（地址 / appid / 主账号）缺失，运行器启动即报错，不会带默认个人值跑测试。

## 五、多环境结构（第1轮 / 第2轮隔离测试）

`personal_config.json` 在「单环境扁平结构」之外，还支持「多环境结构」，便于在 2 个隔离环境分别跑第1轮、第2轮测试。**分享模板 `personal_config.example.json` 本身就是按此结构写的**——内置 `round1_local`（第1轮，本地环境类）与 `round2_devtest`（第2轮，预发布环境类）两组环境参数占位，复制后逐组填入真实值即可：

```json
{
  "default_env": "round1_local",
  "envs": [
    { "name": "round1_local", "base_url": "https://env1...", "appid": "...", "...": "..." },
    { "name": "round2_devtest", "base_url": "https://env2...", "appid": "...", "...": "..." }
  ]
}
```

- **环境选择优先级**：先按 region 过滤（`--region` / `WJX_REGION`，如 cn=国内版 / intl=国际版），再按命令行 `--env <环境name>`（冒烟脚本支持）> 环境变量 `WJX_ENV` > 顶层 `default_env` > 候选中第一个。
- **公共字段回退**：顶层（envs / default_env 之外）的字段视为所有环境共享，仅在某个环境块未定义时才回退使用。
- **向后兼容**：老的「单环境扁平结构」配置（无 `envs` 键）仍按原样生效，无需改动。
- 参考实例放**包外** `~/.workbuddy/wjx-api-test/personal_config.json`（wjx-api-test 本团队真实值，已内置 `round1_local`——第1轮本地环境类 hesong/drunkyong appid 3585——与 `round2_devtest`——第2轮预发布环境 devtest.wjx.cn appid 2043325——两组隔离环境），**仅内部使用、不要随 skill 分享**。

> 深度测试（`api_test_runner.py`）在导入时即加载配置，因此选环境请用环境变量 `WJX_ENV=round2_devtest`；冒烟测试（`smoke_runner.py`）两种都可用（`--env round2_devtest` 或 `WJX_ENV=...`）。

### 冒烟配置的多环境结构

冒烟环境配置（`smoke_config_*.json`）同样支持多环境结构，与个人参数的写法一致：

- **顶层**放各环境**共享**字段：`method` / `timeout` / `tls_verify` / `action_param` / `common_param_generators` / `qps_tiers` / `error_retry` / `error_retry_sleep` / `teardown_enabled` / `env_keywords` / `na_keywords`，以及 `default_env`。
- **`envs` 数组**每组一个隔离环境，各含独立字段：`name`（环境唯一标识，供 `--env` / `WJX_ENV` 选择）、`base_url`、`common_params`（encode/appid/sign）、`account`（main/sub）、`overrides`（该环境专属的业务实例 ID 与数据）。
- **环境选择**：引擎内 `select_smoke_env()` 按 `--env` > `WJX_ENV` > 顶层 `default_env` > `envs[0]` 选定后扁平化；无 `envs` 键的旧扁平配置原样兼容。
- **overrides 按环境独立**：第 1 轮环境生成的 vid 类实例 ID 在第 2 轮环境通常不存在，须分别按各环境真实接口重新生成；未生成的环境相关用例会被 `na_keywords` 判为 N/A。
- 模板 `smoke_config.example.json`（占位符，已内置 cn 2 套 + intl 1 套示例）为包内唯一分发文件；含真实值的实例配置（如 `smoke_config_cw.json`）放**包外** `~/.workbuddy/wjx-api-test/` 并用 `--config` 显式指定——国际版开通后按模板 intl 块复制增填。

## 六、多套环境（国内版 / 国际版）与跨环境纪律

envs 数组的块数不限，用 `region` 字段分组即可支持任意多套环境，例如：

```json
{
  "default_env": "cn_1",
  "envs": [
    { "name": "cn_1",  "region": "cn",   "base_url": "https://国内环境1...", "appid": "..." },
    { "name": "cn_2",  "region": "cn",   "base_url": "https://国内环境2...", "appid": "..." },
    { "name": "intl_1", "region": "intl", "base_url": "https://国际环境1...", "appid": "..." },
    { "name": "intl_2", "region": "intl", "base_url": "https://国际环境2...", "appid": "..." }
  ]
}
```

- **初始模板不必写全**：`personal_config.example.json` 内置 cn 2 套 + intl 1 套示例占位，按需增删 envs 块即可。
- **按环境取参**：运行时先按 `--region` / `WJX_REGION` 过滤（如 `--region intl` 只在国际版环境里选），再按 `--env` / `WJX_ENV` / `default_env` 选定；扁平化后**只有所选环境的参数进入运行时**，跨 region 参数根本不会加载。
- **跨环境纪律（除异常情况外不能跨环境）**：正常用例只许用所选环境参数。仅异常场景测试（跨企业 / 跨租户 / 越权隔离验证）允许显式跨环境：
  - 深度测试：设环境变量 `WJX_CROSS_ENV=<环境name>`（可另配 `WJX_CROSS_CONFIG` 指定其他配置文件、`WJX_CROSS_REGION` 过滤）→ 加载为 `CROSS_CFG`；
  - 冒烟测试：`--cross-env <环境name>`（或 `WJX_CROSS_ENV`）→ 挂到 `ctx.cross_env` 供异常用例取用；
  - 显式加载的跨环境参数带 `_cross_env` 标记，产物可审计；未显式开启时其他环境参数完全不加载（已实测 CROSS_CFG=None）。
- **实例 ID 按环境独立**：vid/uid/submitdata 等业务实例 ID 在各环境互不相通，须按各环境分别生成；未生成时相关用例判 N/A。
